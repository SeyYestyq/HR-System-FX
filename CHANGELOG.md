## 🛠 2. Детальный разбор исправлений и реализаций

### 2.1. `DatabaseManager.java` (Устранение сбоев и Fail-Fast)
* **Было:** Пустой класс, вызывавший ошибки компиляции `cannot find symbol: method testConnection()`, `cannot find symbol: method getConnection()`.
* **Стало:**
  - Загрузка `database.properties` через `ClassLoader.getResourceAsStream()`.
  - Валидация параметров: при отсутствии файла или незаполненных `db.url`, `db.user`, `db.password` выбрасывается информативное `IllegalStateException`.
  - Динамическая загрузка драйвера `Class.forName(driver)`.
  - Метод `testConnection()` безопасно проверяет связь с сервером через `conn.isValid(2)`. Если БД недоступна (например, Docker не запущен), приложение мгновенно переключается на автономный `InMemoryVacancyDao` без падений.

### 2.2. `PostgresVacancyDao.java` (Безопасный доступ к данным без SQL-инъекций)
* **Было:** Класс с заглушкой `throw new UnsupportedOperationException`. Ошибки компиляции из-за нереализованного метода `delete(Long)`.
* **Стало:**
  - Реализованы все методы контракта `VacancyDao`: `findAll()`, `findById()`, `create()`, `update()`, `delete()`.
  - Все SQL-запросы вынесены в `private static final String` константы и параметризованы знаком `?`. Полный запрет склейки строк.
  - Использован SQL JOIN с таблицей `users` для извлечения названия компании работодателя (`u.company_name`, `u.full_name`, `u.email`).
  - При создании вакансии используется `Statement.RETURN_GENERATED_KEYS` для получения присвоенного базой идентификатора `id`.
  - Каждое обращение к БД оборачивается в `try-with-resources` (`Connection`, `PreparedStatement`, `ResultSet`), что исключает утечки соединений в пуле.
  - Любые `SQLException` оборачиваются в типизированное `DatabaseException` с сохранением исходной причины (`cause`).

### 2.3. `CsvExportService.java` (Изолированный экспорт данных)
* **Было:** Метод выбрасывал `UnsupportedOperationException`.
* **Стало:**
  - Полное соблюдение принципа Single Responsibility: класс не импортирует ни одного класса `javafx.*` и занимается только сериализацией данных.
  - В начало файла пишется байтовая последовательность UTF-8 BOM (`0xEF, 0xBB, 0xBF`), гарантирующая открытие кириллицы в Microsoft Excel без искажений кодировки.
  - Реализована санитизация полей: символы `;`, `\r`, `\n` заменяются, исключая сдвиг колонок при экспорте.
  - Потоковая запись через `BufferedWriter` с буфером 8 КБ обеспечивает высокую скорость и минимальный расход ОЗУ.

### 2.4. `FxTasks.java` (Отзывчивый UI и многопоточность)
* **Было:** Пустой класс, контроллеры блокировали UI-поток.
* **Стало:**
  - Обертка над `javafx.concurrent.Task<T>`.
  - Фоновые потоки помечаются как `daemon` (`thread.setDaemon(true)`), поэтому они не препятствуют завершению JVM при закрытии окна.
  - Колбэки `onSuccess` и `onFailure` гарантированно выполняются на JavaFX Application Thread, предотвращая исключения `IllegalStateException: Not on FX application thread`.

### 2.5. `VacancyDialog.java` и `VacancyDialogController.java` (Форма ввода)
* **Было:** Разметка FXML не была связана с контроллером, отсутствовала валидация.
* **Стало:**
  - Привязка всех `@FXML` элементов: `titleField`, `employerComboBox`, `salaryMinField`, `salaryMaxField`, `statusComboBox`, `descriptionArea`, `errorLabel`.
  - Конвертер для `ComboBox<User>` отображает понятную строку `Компания (email)`.
  - На кнопку «Сохранить» повешен перехватчик `EventFilter(ActionEvent.ACTION)`. Если валидация не пройдена (короткое название, отрицательная зарплата, `salaryMax < salaryMin`), событие поглощается (`event.consume()`), окно не закрывается, а ошибочное поле подсвечивается красной рамкой.
  - В режиме редактирования форма автоматически предзаполняется текущими значениями выбранной вакансии.

### 2.6. `StatisticsDialog.java` (Дашборд аналитики)
* **Было:** Заглушка с `UnsupportedOperationException`.
* **Стало:**
  - Окно сверстано программно через `GridPane` и `VBox` с модальностью `APPLICATION_MODAL`.
  - 5 аналитических карточек: «Всего вакансий», «Активных вакансий», «В архиве», «Средняя зарплата от», «Максимальная зарплата».
  - Денежные суммы форматируются с пробелами-разделителями (`175 625 ₽`).
  - Все стили заданы через CSS-классы (`.metric-card`, `.metric-value`, `.metric-title`, `.header-title`), исключая жестко зашитые `setStyle()`.

### 2.7. `MainController.java` (Ядро интерфейса)
* **Было:** Заглушка, приложение не собиралось.
* **Стало:**
  - Реактивная архитектура на `ObservableList<Vacancy>` → `FilteredList<Vacancy>` → `SortedList<Vacancy>`.
  - Живой поиск без задержек по названию, компании и описанию.
  - Фильтры по статусу (`ACTIVE`, `ARCHIVED`, `REJECTED`) и зарплатным диапазонам («до 100 000», «100 000–200 000», «от 200 000»).
  - Кнопка «Сброс» возвращает исходное состояние фильтров.
  - При экспорте снимается снимок `new ArrayList<>(filteredData)` на UI-потоке, а сама запись выполняется в фоне; кнопка экспорта блокируется до завершения, что исключает `ConcurrentModificationException`.
  - Двойной клик по строке таблицы открывает редактирование вакансии.
  - Строки со статусом `ARCHIVED` подсвечиваются полупрозрачным стилем через `PseudoClass`.

## ⚡ 3. Оптимизация производительности и памяти

1. **Минимизация выделения объектов в памяти (Zero Memory Bloat):**
   - Для фильтрации и сортировки используется цепочка `FilteredList` и `SortedList`, оборачивающая исходный список `ObservableList` без дублирования сущностей.
   - Снимок для экспорта (`new ArrayList<>(filteredData)`) копирует лишь 64-битные ссылки на объекты, а не создает глубокие копии сущностей.
2. **Потокобезопасность без утечек дескрипторов:**
   - Все JDBC-соединения, стейтменты и результирующие наборы закрываются в блоках `try-with-resources`.
   - Фоновые потоки `FxTasks` имеют статус `daemon`, что позволяет GC мгновенно освобождать ресурсы при закрытии окна.
3. **Эффективный Stream API:**
   - В `StatisticsService` подсчет общего количества выполняется за $O(1)$ через `vacancies.size()`.
   - Потоки фильтрации и расчета средней/максимальной зарплаты не создают промежуточных коллекций в памяти.
4. **Чистый лог без System.out:**
   - Полное отсутствие `System.out.println` и `printStackTrace()`. Логирование ведется строго через `org.slf4j.Logger`.
