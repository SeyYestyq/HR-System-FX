Контрольная работа №2
Разработка настольного JavaFX-приложения. Защита проекта (по командам) - пояснение кода и ответы на вопросы.

Пример реализации: готовая информационная система находится в архиве с проектом. JavaFX-пример расположен в каталоге javafx-client. Архив с проектом прикреплен в самом низу страницы Контрольной работы №2. Ниже приведены порядок запуска, требования к работе, настройки Maven и параметры подключения.
Подготовка и развертывание системы
Архив содержит не отдельный пример JavaFX, а готовую информационную систему из трёх компонентов: веб-системы с backend и frontend, Android-приложения и JavaFX-приложения. Все три компонента рассчитаны на работу с одним backend и одной базой данных. Поэтому начинать работу сразу с каталога javafx-client не нужно.

1. Веб-система: backend и frontend
Каталог backend. Backend написан на Spring Boot и предоставляет REST API, а frontend находится в backend/src/main/resources/static и открывается в браузере. Эта же часть системы работает с PostgreSQL.

2. Android-приложение
Каталог android-client. Это отдельный мобильный клиент. Он использует тот же REST API, что и остальные клиенты системы.

3. JavaFX-приложение
Каталог javafx-client. Это настольный клиент, который используется как пример для Контрольной работы №2. В готовой системе из архива JavaFX-клиент работает через backend, поэтому для просмотра примера сначала необходимо полностью развернуть систему и запустить серверную часть.

Для выполнения Контрольной работы №2 JavaFX-приложение команды необходимо отдельно подключить через JDBC к базе данных PostgreSQL, созданной в Контрольной работе №1. Добавление, просмотр, редактирование, удаление, поиск и другие операции в своей КР №2 должны выполняться с данными из базы КР №1. Готовый javafx-client используется как пример структуры JavaFX-проекта и организации интерфейса.

Docker обязателен. Перед запуском проекта должен быть установлен и запущен Docker. На Windows используется Docker Desktop. На Linux можно использовать Docker Engine с Docker Compose. Через Docker запускаются PostgreSQL и серверная часть проекта, к которой затем подключается JavaFX-клиент.

Порядок запуска
Распакуйте архив проекта в отдельную папку. Не переносите backend, android-client и javafx-client по отдельности: они относятся к одному проекту.
Убедитесь, что в корне проекта находится файл .env. В нём уже указаны параметры PostgreSQL, JWT, учётная запись администратора и используемые порты.
Запустите Docker и дождитесь, пока он перейдёт в рабочее состояние.
Сначала запустите серверную часть и PostgreSQL. На Windows удобнее выполнить из корня проекта:
powershell -ExecutionPolicy Bypass -File .\backend\start-compose.ps1
То же самое можно выполнить непосредственно через Docker Compose:

docker compose --env-file .env -f backend/docker-compose.yml up -d --wait
После запуска откройте в браузере http://localhost:8080/. Если страница системы открывается, серверная часть запущена.
При необходимости дополнительно проверьте состояние backend по адресу http://localhost:8080/actuator/health.
Войдите в веб-интерфейс под учётной записью администратора. Логин и пароль приведены ниже в отдельном разделе.
Только после этого переходите в каталог javafx-client и запускайте JavaFX-приложение.
Для Windows:

cd javafx-client
.\run.ps1
Либо обычной командой Maven:

cd javafx-client
mvn javafx:run
JavaFX-клиент по умолчанию обращается к REST API по адресу http://127.0.0.1:8080/api. Он не создаёт базу данных и не запускает Spring Boot самостоятельно. Его задача состоит в подключении к уже работающей системе.

Важно: если сначала запустить только javafx-client, окно приложения может открыться, но авторизация, загрузка студентов, групп и другие операции будут недоступны, потому что REST API и PostgreSQL ещё не запущены. Поэтому последовательность всегда одна: Сначала Docker, затем PostgreSQL и backend, после этого проверка веб-системы и только затем JavaFX..
Android-приложение также входит в этот архив и работает с тем же backend. Для выполнения Контрольной работы №2 запуск Android-клиента не требуется, но удалять или переносить его из общей структуры проекта не нужно.

Общая задача
На основе предметной области своего варианта разработать полноценное настольное приложение на JavaFX для работы с данными системы.

Приложение должно позволять пользователю работать с основными сущностями через графический интерфейс, а не через консоль.

JavaFX-приложение, выполняемое в рамках КР №2, должно иметь отдельное JDBC-подключение к PostgreSQL и работать с базой данных, созданной командой в КР №1. Готовый REST API из архива используется для запуска и изучения примера, но не заменяет подключение собственной работы к своей базе данных.

Настройка подключения к базе данных
В готовой системе из архива JavaFX-клиент не подключается к PostgreSQL напрямую. Он обращается к backend по REST API. Это относится именно к демонстрационному проекту. В собственной Контрольной работе №2 необходимо сделать отдельное подключение JavaFX к PostgreSQL через JDBC.

Работа готового примера организована следующим образом:

JavaFX-клиент отправляет запросы в REST API.
REST API обрабатывается приложением Spring Boot.
Spring Boot выполняет операции с PostgreSQL.
Подключение JavaFX к PostgreSQL для КР №2
В своей КР №2 используйте базу данных PostgreSQL, созданную в КР №1. Параметры подключения рекомендуется хранить отдельно от Java-классов, например в файле src/main/resources/database.properties.

db.url=jdbc:postgresql://localhost:5432/имя_базы_из_КР1
db.user=пользователь_базы_данных
db.password=пароль_базы_данных
Имя базы данных, имя пользователя, пароль и порт должны соответствовать настройкам базы данных вашей команды из КР №1. Если PostgreSQL работает на другом порту, укажите фактический порт.

SQL-запросы рекомендуется вынести в отдельные классы доступа к данным, например DAO. Не размещайте SQL непосредственно в обработчиках кнопок JavaFX.

Настройки Spring Boot в готовом примере
Файл: backend/src/main/resources/application.yml.

spring:
  datasource:
    url: ${SPRING_DATASOURCE_URL:jdbc:postgresql://localhost:5432/student_hub}
    username: ${SPRING_DATASOURCE_USERNAME:student_hub}
    password: ${SPRING_DATASOURCE_PASSWORD:student_hub}
Значения после двоеточия являются локальными значениями по умолчанию. При наличии переменных окружения SPRING_DATASOURCE_URL, SPRING_DATASOURCE_USERNAME и SPRING_DATASOURCE_PASSWORD используются именно они.

При подключении к PostgreSQL с компьютера для конфигурации из архива используются: jdbc:postgresql://localhost:55432/student_hub, пользователь student_hub_app, пароль Db1!D90F176A0758B82E72A92FC9BE3F8652.

Корневой файл .env
Файл .env находится в корне проекта, то есть рядом с каталогами backend, javafx-client и android-client. Для проекта из архива используется следующая конфигурация:

POSTGRES_DB=student_hub
POSTGRES_USER=student_hub_app
POSTGRES_PASSWORD=Db1!D90F176A0758B82E72A92FC9BE3F8652

JWT_SECRET_BASE64=Q3siV/Xs6wPsaeW8EWmG/UsvD4QwOvoW/OKPaO8pU+HDvXBTZrmKeqcaO/y12PrSgJRSy0f17vfM2ZpgbpdjMg==
JWT_ISSUER=student-hub
ACCESS_TOKEN_MINUTES=15
REFRESH_TOKEN_DAYS=14

BOOTSTRAP_ADMIN_EMAIL=admin@example.org
BOOTSTRAP_ADMIN_NAME=System Administrator
BOOTSTRAP_ADMIN_PASSWORD=Adm1!750DF9E52689A0B47E4DE85BC5C8AAC0

CORS_ALLOWED_ORIGINS=http://localhost:8080
COOKIE_SECURE=false
PERMANENT_DELETE_ENABLED=false
APP_PORT=8080

POSTGRES_PORT=55432
POSTGRES_DB, POSTGRES_USER и POSTGRES_PASSWORD задают имя базы, пользователя и пароль PostgreSQL. POSTGRES_PORT=55432 означает, что с компьютера PostgreSQL доступен на порту 55432; внутри Docker-сети контейнер базы продолжает использовать стандартный порт 5432.

Параметры JWT_*, ACCESS_TOKEN_MINUTES и REFRESH_TOKEN_DAYS относятся к авторизации. Параметры BOOTSTRAP_ADMIN_* задают первоначальную учётную запись администратора. APP_PORT=8080 задаёт порт Spring Boot.

Файл backend/docker-compose.yml получает значения из корневого .env и передаёт параметры подключения backend-приложению через SPRING_DATASOURCE_*. Поэтому при обычном запуске проекта через Docker Compose вручную менять application.yml не требуется.

Адрес REST API в готовом JavaFX-примере
По умолчанию JavaFX-клиент обращается к API по адресу http://localhost:8080/api. При запуске через готовый скрипт используется системное свойство studenthub.api.

mvn -Dstudenthub.api=http://127.0.0.1:8080/api javafx:run
Готовые скрипты запуска находятся в javafx-client/run.ps1 и javafx-client/run.sh. Если backend работает на другом компьютере или порту, изменяется именно адрес API, а не пароль PostgreSQL внутри JavaFX-клиента.

Часть 1. Главное окно приложения
Создайте главное окно, из которого доступны основные функции системы.

В главном окне должны быть предусмотрены:

просмотр списка основных объектов предметной области;
добавление новой записи;
редактирование выбранной записи;
удаление записи с подтверждением;
поиск;
фильтрация;
сортировка;
обновление данных;
переход к статистике;
экспорт данных.
Интерфейс должен быть понятным: пользователь должен видеть, какие действия доступны и к каким данным они относятся.

Пример расположения элементов интерфейса: см. архив с проектом, каталог javafx-client.
Часть 2. Табличное представление данных
Основные данные предметной области необходимо вывести в TableView.

Таблица должна:

отображать основные поля сущности;
поддерживать выбор строки;
корректно обновляться после добавления, изменения или удаления данных;
иметь понятные заголовки столбцов;
не выводить пользователю технические данные, которые ему не нужны.
Для данных, отображаемых в JavaFX, используйте подходящие коллекции JavaFX, в том числе ObservableList, когда это оправдано.

Пример работы с таблицами JavaFX: см. архив с проектом, каталог javafx-client.
Часть 3. Добавление, редактирование и удаление
Для основной сущности варианта реализуйте полный набор CRUD-операций через графический интерфейс.

ДобавлениеПользователь вводит данные в форму. После успешного сохранения новая запись появляется в интерфейсе.
РедактированиеФорма должна открываться с текущими значениями выбранного объекта.
УдалениеПеред удалением обязательно запросить подтверждение пользователя.
ПросмотрОсновные сведения об объекте должны быть доступны без обращения к консоли или БД вручную.
Часть 4. Работа со связанными сущностями
Приложение должно учитывать связи, созданные в базе данных в КР №1.

Если сущность содержит внешние ключи, пользователю нельзя предлагать вручную вводить идентификатор связанной записи, если можно выбрать объект из списка.

Для выбора связанных сущностей используйте подходящие элементы управления JavaFX, например ComboBox, ListView или отдельное диалоговое окно.

Валидация данных
Все пользовательские данные необходимо проверять до сохранения.

Обязательно проверяются:

пустые обязательные поля;
числовые значения и допустимые диапазоны;
даты и их логическая корректность;
длина строк;
уникальные значения, если это предусмотрено моделью;
ссылки на существующие связанные сущности;
бизнес-ограничения вашего варианта.
При ошибке пользователь должен получить понятное сообщение: какое поле заполнено неверно и что необходимо исправить.

Диалоговые окна
Используйте диалоговые окна JavaFX для действий, которые требуют отдельной формы или подтверждения.

добавление объекта;
редактирование объекта;
подтверждение удаления;
сообщение об ошибке;
сообщение об успешном выполнении критически важной операции, если оно действительно необходимо.
Не используйте консольные сообщения вместо нормальной обратной связи в интерфейсе.

Поиск, фильтрация и сортировка
Реализуйте отдельный блок работы с большим списком данных.

Поиск
Должен выполняться минимум по нескольким смысловым полям основной сущности.

Фильтрация
Предусмотрите минимум два полезных фильтра, соответствующих предметной области. Например: статус, категория, группа, период дат, тип объекта или другое поле вашего варианта.

Сортировка
Реализуйте сортировку минимум по двум параметрам. Встроенная сортировка TableView может использоваться, но студент должен понимать, как она работает.

Статистика
В приложении должен быть отдельный блок статистики.

Рассчитайте не менее 5 показателей, имеющих смысл для вашей предметной области.

Например, это могут быть:

общее количество объектов;
количество объектов по статусам или категориям;
минимальное и максимальное значение числового показателя;
среднее значение;
количество записей за выбранный период;
доля или процент объектов определённого типа.
Конкретные показатели выбираются командой исходя из смысла своей системы.

Экспорт данных
Добавьте выгрузку данных из приложения.

Минимальное требование: экспорт текущего набора данных в один из форматов:

.xlsx;
.csv.
Путь сохранения файла пользователь выбирает через FileChooser. Нельзя жёстко прописывать путь к файлу на компьютере разработчика.

FXML
Интерфейс ключевых окон должен быть вынесен в FXML. Не требуется строить весь интерфейс программно в одном Java-классе.

Необходимо понимать назначение:

FXML-файла;
Controller;
fx:id;
обработчиков событий;
связи между элементами интерфейса и контроллером.
Ориентир по организации JavaFX-приложения: см. архив с проектом, каталог javafx-client. FXML-разметку для своей работы необходимо добавить в соответствии с требованиями этого раздела.
CSS и оформление интерфейса
Основное визуальное оформление вынесите в CSS.

Минимально должны быть оформлены:

кнопки основных действий;
таблицы;
формы ввода;
заголовки и основные контейнеры;
состояния ошибки или предупреждения, если они используются.
Интерфейс должен оставаться читаемым и аккуратным при изменении размера окна в разумных пределах.

Архитектура приложения
Не размещайте весь код приложения в одном Controller.

Разделите ответственность как минимум между следующими уровнями:

Слой	Назначение
View / FXML	Отображение интерфейса и элементов управления.
Controller	Получение действий пользователя и координация работы интерфейса.
Service	Бизнес-правила и операции предметной области.
Repository / DAO	Чтение и запись данных.
Database	Хранение данных, ограничения и связи.
Пример организации JavaFX-проекта: см. архив с проектом, каталог javafx-client.
Что делать нельзя
размещать весь интерфейс и всю логику в одном классе;
писать SQL непосредственно в обработчике кнопки;
дублировать один и тот же код в разных контроллерах;
оставлять пустые обработчики или неработающие кнопки;
игнорировать исключения с помощью пустого catch;
показывать пользователю stack trace вместо понятного сообщения;
хранить пароль БД непосредственно в исходном коде;
жёстко прописывать абсолютные пути к файлам;
принимать любые данные без валидации;
использовать консоль как основной интерфейс после перехода на JavaFX.
Рекомендуемая структура проекта
Проект должен быть разделён по назначению классов: интерфейс, контроллеры, модели, сервисы, доступ к данным и вспомогательные компоненты не следует складывать в один пакет.
