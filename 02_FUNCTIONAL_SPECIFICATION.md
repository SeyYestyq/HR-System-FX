# 02. Функциональная спецификация настольного JavaFX-приложения (КР2)

> **Проект:** Система подбора специалистов и управления вакансиями (**HireSystem / HR-система**)  
> **Стек:** Java 21, JavaFX 21, Maven, PostgreSQL 15 (Docker), JDBC, JUnit 5  
> **Ориентир:** Требования из `2.txt` и архитектурный шаблон `student-hub-suite-rebuilt`

---

## 1. Назначение и контекст системы

Настольное приложение **HireSystem JavaFX Client** заменяет консольный интерфейс из КР №1 на современный оконный графический интерфейс. Приложение подключается напрямую через JDBC к базе данных PostgreSQL из КР №1 и предоставляет пользователю (HR-менеджеру / рекрутеру) удобные инструменты управления вакансиями, фильтрации кандидатов, расчета статистики и выгрузки отчетов.

---

## 2. Экранные формы и элементы интерфейса

### 2.1. Главное окно (`MainView.fxml`)
Главное окно разделено на функциональные зоны:

1. **Верхний колонтитул (Header / Brand bar):**
   - Бренд `HireSystem` и подзаголовок «Управление вакансиями и специалистами»;
   - Индикатор статуса подключения к БД (`🟢 PostgreSQL подключен` / `🟠 Автономный режим (Stub)`);
   - Кнопка **«⟳ Обновить»** — перечитывает список из БД в фоне.
2. **Панель инструментов и действий (Toolbar):**
   - Кнопка **«+ Новая вакансия»** — открывает модальный `VacancyDialog`;
   - Кнопка **«✎ Редактировать»** — активна только при выборе строки, открывает `VacancyDialog` с текущими значениями;
   - Кнопка **«🗑 Удалить»** — красная (`danger-button`), требует подтверждения;
   - Кнопка **«📊 Статистика (5 показателей)»** — открывает `StatisticsDialog` с пятью метриками;
   - Кнопка **«📥 Экспорт в CSV»** — открывает `FileChooser` и выгружает отфильтрованные строки.
3. **Панель поиска и фильтрации:**
   - **Поле живого поиска (`TextField`)**: мгновенная фильтрация по вхождению подстроки (без учета регистра) в `title`, `employerCompanyName` и `description`.
   - **Фильтр по статусу (`ComboBox<String>`)**: `Все статусы`, `ACTIVE`, `ARCHIVED`, `REJECTED`.
   - **Фильтр по диапазону зарплаты (`ComboBox<String>`)**: `Вся зарплата`, `до 100 000`, `100 000–200 000`, `от 200 000`. Сравнение ведется по `salaryMin` (для `от 200 000` — `salaryMin >= 200 000`).
   - Кнопка **«✕ Сброс»** возвращает поиск и оба фильтра к значениям по умолчанию.
4. **Центральная таблица данных (`TableView<Vacancy>`):**
   - Колонки: `ID`, `Название вакансии`, `Работодатель / Компания` (из `employerCompanyName`, иначе `ID #<employerId>`), `Зарплата от (₽)`, `Зарплата до (₽)`, `Статус`.
   - Сортировка по столбцам включена, таблица растягивается по ширине окна.
   - При двойном клике по строке — открытие режима редактирования.
5. **Нижняя строка состояния (Status Bar):**
   - Счетчик: «Показано: X из Y вакансий» — пересчитывается на каждое изменение фильтров и загрузку данных.

---

### 2.2. Модальный диалог добавления и редактирования (`VacancyDialog`)
Открывается как модальное окно (`Modality.APPLICATION_MODAL`) с блокировкой родительского окна.

**Состав полей формы:**
1. **Название вакансии (`TextField`)**:
   - Обязательное поле. Длина от 3 до 100 символов.
2. **Работодатель (`ComboBox<User>`) — Связанная сущность!**:
   - Выпадающий список всех зарегистрированных работодателей из таблицы `users` (где `role = 'EMPLOYER'`).
   - Отображает `company_name (email)`.
   - ❌ **Запрещен** ручной ввод числового `employer_id`.
3. **Минимальная зарплата (`TextField` с числовой валидацией)**:
   - Неотрицательное число или пустое (если зарплата не указана).
4. **Максимальная зарплата (`TextField` с числовой валидацией)**:
   - Неотрицательное число;
   - Бизнес-правило: `salary_max >= salary_min`.
5. **Описание вакансии (`TextArea`)**:
   - Текстовое описание требований и обязанностей.
6. **Статус вакансии (`ComboBox<VacancyStatus>`)**:
   - Доступен для редактирования (`ACTIVE`, `ARCHIVED`, `REJECTED`). При создании новой по умолчанию `ACTIVE`.
7. **Кнопки управления:**
   - «Сохранить» (валидирует поля перед закрытием диалога);
   - «Отмена» (закрывает диалог без сохранения изменений).

---

### 2.3. Диалог аналитики (`StatisticsDialog`)
Модальное окно (`Modality.APPLICATION_MODAL`), создаётся статическим `StatisticsDialog.show(owner, dto)`.

- **Пять карточек** в `GridPane`: «Всего вакансий», «Активных вакансий», «В архиве», «Средняя зарплата от», «Максимальная зарплата».
- Значения берутся из `StatisticsDto`; зарплаты форматируются как `%,d ₽`.
- Карточки стилизованы CSS-классами `metric-card`, `metric-value`, `metric-title`; таблицы стилей наследуются от главного окна.
- Кнопка **«Закрыть»** закрывает окно.

## 3. Сценарии использования (Use Cases)

### UC-1: Добавление новой вакансии
1. Пользователь нажимает кнопку «+ Новая вакансия».
2. Сервис загружает список работодателей из БД: `List<User> employers`.
3. Открывается форма `VacancyDialog` в режиме создания.
4. Пользователь заполняет поля, выбирает компанию из выпадающего списка и жмет «Сохранить».
5. Срабатывает валидация:
   - Если название пустое или зарплата отрицательная — отображается ошибка, окно остается открытым.
   - Если данные корректны — сервис вызывает `vacancyDao.create(newVacancy)`.
6. База данных генерирует новый `id`.
7. Новая вакансия добавляется в главный `ObservableList<Vacancy>`.
8. Таблица на экране мгновенно обновляется без полной перезагрузки, строка подсвечивается.
9. Выводится сообщение `UiUtils.showInfoAlert("Успех", "Вакансия успешно добавлена!")`.

### UC-2: Редактирование вакансии
1. Пользователь выбирает строку в таблице и нажимает «Редактировать» (или дважды кликает по строке).
2. Форма `VacancyDialog` открывается с заполненными текущими значениями выбранной вакансии.
3. В `ComboBox<User>` автоматически выбран текущий работодатель вакансии.
4. Пользователь корректирует поля (например, увеличивает зарплату) и нажимает «Сохранить».
5. Проводится валидация. При успехе вызывается `vacancyService.updateVacancy(vacancy)`.
6. `vacancyDao.update(...)` выполняет SQL `UPDATE`.
7. Элемент обновляется в `ObservableList`, таблица перерисовывается.

### UC-3: Удаление вакансии с подтверждением
1. Пользователь выбирает вакансию в таблице и жмет «Удалить».
2. Приложение отображает модальный диалог подтверждения `UiUtils.showConfirmDialog`:  
   *«Вы уверены, что хотите удалить вакансию "[Название]"? Это действие необратимо.»*
3. Если пользователь нажимает «Отмена» — операция прерывается.
4. Если пользователь нажимает «Удалить»:
   - Вызывается `vacancyService.deleteVacancy(id)`.
   - Выполняется SQL `DELETE FROM vacancies WHERE id = ?`.
   - Запись удаляется из `ObservableList`.
   - Таблица обновляется, выводится уведомление об удалении.

### UC-4: Живой поиск и фильтрация (без блокировки)
1. Пользователь вводит текст в поле поиска (например, «Java»).
2. Список мгновенно фильтруется в памяти через `FilteredList<Vacancy>` по `title`, `description` и компании работодателя (регистронезависимо).
3. Дополнительно учитываются фильтр по статусу (`ACTIVE`/`ARCHIVED`/`REJECTED`) и фильтр по диапазону зарплаты (`salaryMin`).
4. Предикат объединяет все три условия; счетчик в статус-баре пересчитывается.

### UC-5: Аналитический дашборд (5 показателей)
1. Пользователь нажимает «📊 Статистика (5 показателей)».
2. `StatisticsService.calculateMetrics()` в фоне через `FxTasks` считает метрики, результат показывается в `StatisticsDialog`:
   - **Всего вакансий** (`totalVacancies`);
   - **Активных вакансий** (`activeVacancies`);
   - **В архиве** (`archivedVacancies`);
   - **Средняя зарплата от** (`averageSalaryMin`, формат `%,d ₽`);
   - **Максимальная зарплата** (`maxSalary`, формат `%,d ₽`).
3. Диалог модальный (`APPLICATION_MODAL`), карточки стилизованы классами `metric-card`, `metric-value`, `metric-title`. Закрывается кнопкой «Закрыть».

### UC-6: Экспорт данных в CSV через FileChooser
1. Пользователь нажимает «📥 Экспорт в CSV».
2. Открывается `FileChooser` (заголовок «Сохранить выгрузку вакансий в CSV», имя по умолчанию `vacancies_export.csv`, фильтр `CSV файлы (*.csv)`). Путь не хардкодится.
3. На FX-потоке снимается снимок текущего отфильтрованного списка: `new ArrayList<>(filteredData)`.
4. `CsvExportService.export(snapshot, target)` выполняется в фоне через `FxTasks`; на время выгрузки кнопка экспорта блокируется. Файл пишется в `UTF-8` с BOM, разделитель `;`, заголовок: `ID;Название вакансии;Компания;Зарплата от;Зарплата до;Статус;Описание`.
5. При успехе — «Экспорт завершен» с абсолютным путём файла; при ошибке — «Ошибка экспорта».

## 4. Бизнес-правила и матрица валидации

| Поле | Правило валидации | Исключение / Сообщение об ошибке |
|---|---|---|
| `Название вакансии` | Не null, не пустое, от 3 до 100 символов | `ValidationException`: "Название вакансии обязательно и должно содержать от 3 до 100 символов." |
| `Работодатель` | Обязательно выбран из ComboBox (`employer != null`) | `ValidationException`: "Необходимо выбрать работодателя из списка зарегистрированных компаний." |
| `Зарплата от` | Если указана: `>= 0`, только целое положительное число | `ValidationException`: "Минимальная зарплата не может быть отрицательной." |
| `Зарплата до` | Если указана: `>= 0` и `>= salary_min` | `ValidationException`: "Максимальная зарплата не может быть меньше минимальной." |
| `Статус вакансии` | Значение из enum (`ACTIVE`, `ARCHIVED`, `REJECTED`) | При попытке архивировать уже архивную: `BusinessException`: "Вакансия уже находится в архиве." |
| `Удаление` | Обязательное подтверждение в UI | Диалог `Confirmation`: отмена при отказе пользователя. |
